# 小文 AI 每日自动更新屏保 PRD

> 文档版本：V0.1
> 更新时间：2026-07-27
> 文档状态：待研发评审
> 适用项目：小文 AI 阅读壁纸生成器
> 目标版本：V1.1 服务端自动生成 / V1.2 BOOX APK 自动同步
> 文档目的：明确固定模板、每日自动取数、服务端生成 JPG、BOOX 自动同步及小程序能力边界。

> 重要边界：当前公开网页采用无账号、无数据库方案，Skill Key 只保存在用户浏览器，因此只能在用户打开网页时生成。本文描述的是未来用户主动开启“每日自动更新”后的独立版本；只有该功能才需要经过明确授权在服务端加密保存 Key、模板配置和最新图片。

---

## 1. 需求摘要

用户完成一次屏保设计后，可以将当前配置保存为“每日屏保”。

系统每天自动查询最新阅读数据，使用同一套模板、字体、设备尺寸、版式和装饰重新生成屏保。模板视觉保持不变，只更新日期、书名、阅读时长、阅读记录、划线等动态数据。

```text
用户配置一次模板
  -> 保存每日屏保订阅
  -> 服务端定时查询阅读数据
  -> 使用固定模板重新生成 JPG
  -> 发布最新图片版本
  -> BOOX APK 自动下载并应用
```

产品最终目标：

- 用户不需要每天打开网页重新生成。
- 模板视觉不因每日任务发生随机变化。
- 数据查询失败时保留上一张可用屏保。
- BOOX 设备可通过 APK 自动获取最新屏保。
- 微信小程序可查看、下载当天屏保，但不承诺关闭小程序后的自动换屏。

## 2. 背景与问题

### 2.1 当前流程

当前 Web 版本已经验证以下链路可行：

1. 用户连接微信读书 Skill Key。
2. 用户选择数据源、模板、设备、方向、字体和模板选项。
3. 页面请求服务端读取数据并生成 SVG。
4. 浏览器将 SVG 转换为 JPG。
5. 用户手动下载，再自行放入 BOOX。

### 2.2 用户问题

- 每天都要重新打开网页并点击生成。
- 模板设置无法保存为长期任务。
- 网页关闭后无法继续运行定时任务。
- 新图片无法自动进入 BOOX 屏保。
- 当前 JPG 在浏览器端转换，不同 WebView 或小程序环境可能产生字体与渲染差异。

### 2.3 机会

将“模板配置”与“每日阅读数据”分开保存，并把最终 JPG 统一放到服务端生成，可以让 Web、APK、小程序获得同一张成品图。

## 3. 产品目标

### 3.1 核心目标

1. 用户只需配置一次屏保。
2. 系统按北京时间每天自动查询最新数据。
3. 同一订阅始终使用固定模板配置。
4. 服务端生成固定尺寸 JPG，保证各客户端获得相同文件。
5. BOOX APK 自动下载并应用最新屏保。
6. 失败时不破坏设备上已有屏保。

### 3.2 成功指标

| 指标 | 首期目标 |
| --- | --- |
| 每日任务成功率 | 大于等于 98% |
| 数据日期准确率 | 100%，按 Asia/Shanghai 解释 |
| 图片尺寸准确率 | 100% |
| 模板配置保持率 | 100%，非数据元素不变化 |
| APK 日同步成功率 | 大于等于 95% |
| 失败后旧图可用率 | 100% |
| Skill Key 明文泄露 | 0 次 |

### 3.3 非目标

- 不在本版本开发模板商城。
- 不在本版本接入 AI 生图。
- 不保证所有 BOOX 设备拥有完全一致的灰阶观感。
- 不承诺 Android 后台任务精确到某一分钟执行。
- 小程序不承诺关闭后自动修改 BOOX 屏保。
- 文石真实阅读数据接口未确认前，不进入正式自动更新。

## 5. 用户与使用场景

### 5.1 目标用户

- 使用 BOOX 设备阅读或展示屏保的用户。
- 使用微信读书并愿意连接 Skill Key 的用户。
- 希望阅读记录每天自动出现在墨水屏上的用户。

### 5.2 核心场景

场景 A：用户在 Web 中完成“本月阅读记录”设计，开启每日更新。第二天服务端自动读取最新数据，模板不变，月历增加当天阅读记录。

场景 B：用户安装 BOOX APK。APK 每天自动检查最新图片，下载并替换设备屏保。

场景 C：微信读书查询失败。系统继续保留昨天的屏保，不输出空白图片。

场景 D：用户修改字体或模板。保存后生成新的配置版本，后续每日任务使用新版本。

场景 E：用户只使用小程序。打开小程序时看到当天最新屏保，并手动保存或推送。

## 6. 关键产品原则

### 6.1 模板不变

开启每日更新后，以下内容必须冻结：

- `templateKey`
- BOOX 设备与目标分辨率
- 横版 / 竖版
- 模板风格
- 字体
- 字体大小
- 贴纸开关
- 摆件选择与位置
- 书柜名称、描述
- 小票商店名称、采购员等自定义字段
- 随机种子 `shuffleSeed`
- 其他场景专属选项

每日只允许变化：

- 阅读日期
- 每日阅读时长
- 阅读天数
- 本月或本周总时长
- 书目
- 封面
- 划线与批注
- 进度
- 数据更新时间

### 6.2 无新数据不换图

服务端对标准化阅读数据计算 `dataHash`：

- `dataHash` 与上一版本相同：不生成新版本。
- `dataHash` 变化：生成新 JPG，并更新 Manifest。
- 用户手动修改模板：即使数据不变，也生成新版本。

### 6.3 失败不覆盖

以下情况不得覆盖上一张成功图片：

- Skill Key 失效。
- 微信读书网关超时。
- 返回数据结构异常。
- 字体读取失败。
- SVG 或 JPG 渲染失败。
- 对象存储上传失败。
- 图片校验失败。

## 7. 完整用户流程

### 7.1 Web 开启每日屏保

1. 用户连接微信读书。
2. 用户打开任一场景。
3. 用户配置模板并生成成功预览。
4. 用户点击“设为每日屏保”。
5. 页面打开确认弹窗。
6. 用户选择更新时间，默认北京时间 06:00。
7. 用户确认设备、模板和数据源。
8. 系统立即执行一次真实生成。
9. 成功后创建订阅。
10. 页面显示“每日更新已开启”。

确认弹窗字段：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| 订阅名称 | 模板名称 | 可自定义 |
| 数据源 | 当前数据源 | 首期只允许微信读书 |
| 更新频率 | 每天 | 首期固定 |
| 更新时间 | 06:00 | Asia/Shanghai |
| BOOX 设备 | 当前设备 | 保存分辨率 |
| 仅数据变化时更新 | 开启 | 默认开启 |

### 7.2 Web 管理每日屏保

首页增加“每日屏保”状态入口。

状态页展示：

- 开启 / 暂停。
- 当前模板。
- 当前设备。
- 数据源。
- 上次成功时间。
- 上次数据日期。
- 下次计划时间。
- 当前图片版本。
- 最近一次错误。
- “立即更新”按钮。
- “编辑模板”按钮。
- “暂停自动更新”按钮。
- “删除每日屏保”按钮。

### 7.3 编辑订阅

用户点击“编辑模板”：

1. 打开原场景弹窗。
2. 自动载入已保存配置。
3. 用户修改并生成预览。
4. 点击“保存到每日屏保”。
5. 配置版本加一。
6. 立即生成新图片。
7. 后续定时任务使用新配置。

### 7.4 关闭订阅

暂停：

- 不再执行每日生成。
- 保留配置和历史图片。
- APK 保持最后一张图片。

删除：

- 删除订阅和设备绑定。
- 删除 Skill Key 需要单独操作，不与删除订阅联动。
- 历史图片按数据保留策略清理。

## 8. 每日任务逻辑

### 8.1 调度时间

- 统一使用 `Asia/Shanghai`。
- 默认每天 06:00。
- 部署平台若只支持 UTC，则使用 `22:00 UTC` 触发次日北京时间 06:00。
- 调度时间不用于解释阅读数据日期，阅读日期始终按北京时间解析。

### 8.2 单次任务步骤

```text
读取启用中的订阅
  -> 获取分布式锁
  -> 验证 Skill Key
  -> no-store 查询微信读书
  -> 标准化数据并按北京时间处理日期
  -> 计算 dataHash
  -> 判断是否需要生成
  -> 使用固定配置生成 SVG
  -> 服务端转换为 JPG
  -> 校验尺寸、文件大小和 SHA-256
  -> 上传对象存储
  -> 更新 Manifest
  -> 写入成功日志
  -> 释放锁
```

### 8.3 自动重试

建议重试策略：

- 第一次失败：10 分钟后。
- 第二次失败：30 分钟后。
- 第三次失败：2 小时后。
- 三次均失败：当天标记失败，保留旧图。

以下错误不自动重试：

- Skill Key 明确失效。
- 用户已删除连接。
- 模板配置无法解析。
- 字体许可证或文件已删除。

### 8.4 幂等要求

同一订阅、同一自然日、同一配置版本只允许产生一个成功版本。

建议幂等键：

```text
subscriptionId + yyyy-MM-dd + configVersion + dataHash
```

## 9. 图片生成与发布

### 9.1 服务端生成 JPG

当前浏览器端 Canvas 转 JPG 必须迁移到服务端。

要求：

- SVG 仍由现有模板引擎生成。
- 服务端使用固定版本的 SVG 光栅化引擎。
- 字体必须由服务端加载或嵌入。
- JPG 背景固定为白色。
- 默认质量 95。
- 不依赖浏览器、WebView 或小程序 Canvas。
- 相同输入必须得到相同布局。

### 9.2 输出文件

版本文件：

```text
/users/{userId}/subscriptions/{subscriptionId}/versions/{version}.jpg
```

最新清单：

```text
/users/{userId}/subscriptions/{subscriptionId}/manifest.json
```

Manifest 示例：

```json
{
  "subscriptionId": "sub_xxx",
  "version": 28,
  "configVersion": 3,
  "dataDate": "2026-07-27",
  "generatedAt": "2026-07-27T06:02:10+08:00",
  "width": 1264,
  "height": 1680,
  "mimeType": "image/jpeg",
  "sha256": "xxx",
  "fileSize": 482310,
  "imageUrl": "https://cdn.example.com/.../28.jpg"
}
```

### 9.3 缓存规则

- 版本 JPG 使用长期缓存。
- Manifest 禁止长期缓存，支持 `ETag`。
- APK 每次先请求 Manifest。
- 版本未变化时不重复下载 JPG。

### 9.4 历史版本

- 默认保留最近 7 个成功版本。
- 当前版本不得被清理。
- 失败任务不生成版本文件。

## 10. BOOX APK 需求

### 10.1 产品定位

APK 是“每日屏保同步器”，不是完整重写 Web 产品。

首期职责：

- 绑定用户。
- 选择一个每日屏保订阅。
- 后台检查 Manifest。
- 下载并校验 JPG。
- 将 JPG 保存到 BOOX 可读取的位置。
- 触发系统或屏保应用重新读取。

### 10.2 首次使用

1. 用户在 BOOX 安装 APK。
2. 打开 APK。
3. 使用二维码或短码绑定 Web 账号。
4. 选择每日屏保。
5. 授予必要的图片或文件权限。
6. 点击“测试同步”。
7. 图片下载并应用成功。
8. 用户开启“每日自动同步”。

### 10.3 APK 首页

展示：

- 当前屏保缩略图。
- 当前订阅名称。
- 图片版本。
- 上次检查时间。
- 上次成功时间。
- 下次计划检查。
- 自动同步开关。
- “立即同步”按钮。
- “重新绑定”按钮。

### 10.4 后台任务

- 使用唯一名称注册周期任务，避免重复任务。
- 默认每天检查一次。
- APP 启动时执行补偿检查。
- 网络恢复时允许补偿检查。
- 新版本下载成功前不得删除旧图。
- 下载完成后校验 SHA-256、尺寸和 MIME。
- 校验通过后原子替换本地文件。

说明：

- Android 后台调度不是精确定时器。
- BOOX 固件可能限制后台运行。
- 需要在目标设备测试省电策略、开机启动和文件访问权限。

### 10.5 APK 错误状态

| 状态 | 用户提示 | 处理 |
| --- | --- | --- |
| 无网络 | 等待网络 | 保留旧图 |
| 登录失效 | 请重新绑定 | 停止下载 |
| 无新版本 | 已是最新 | 不下载 |
| 下载失败 | 稍后重试 | 保留旧图 |
| 校验失败 | 图片不完整 | 删除临时文件 |
| 文件权限失败 | 请授权图片权限 | 引导设置 |
| BOOX 应用未刷新 | 已下载，等待设备刷新 | 提供手动刷新 |

### 10.6 需要研发验证的 BOOX 能力

研发必须在真实设备上确认：

- 屏保图片实际读取目录。
- Android 分区存储限制。
- 是否能通过 MediaStore 保存。
- 是否需要媒体扫描通知。
- 文石屏保应用是否自动识别文件替换。
- 是否有正式屏保设置 API。
- Leaf、Poke、Note 系列差异。
- 后台任务在 BOOX 省电策略下的存活情况。

未确认正式 API 前，不在产品文案中承诺“自动设为系统屏保”，只承诺“自动下载最新屏保”。

## 11. 微信小程序需求与边界

### 11.1 可实现

- 查看每日屏保状态。
- 修改模板配置。
- 手动立即更新。
- 显示当天最新 JPG。
- 下载或保存图片。
- 打开文石推送页面。

### 11.2 不可承诺

- 小程序关闭后持续运行。
- 每天自动下载到 BOOX。
- 直接访问 BOOX 本地阅读数据或文件。
- 在没有设备侧 APK 或正式推送接口时自动替换 BOOX 屏保。

### 11.3 页面文案

小程序必须使用：

```text
今日屏保已更新
```

不得使用：

```text
BOOX 屏保已自动更换
```

除非设备侧已返回明确成功状态。

## 12. 数据源规则

### 12.1 微信读书

V1.1 正式支持：

- Skill Key 加密保存。
- 每次任务实时请求，不使用应用层历史缓存。
- 日期按 `Asia/Shanghai` 解释。
- Skill Key 失效后暂停订阅，并在用户下次打开产品时提示。

数据时效说明：

- 系统每次任务请求微信读书最新数据。
- 微信读书内部聚合可能存在短暂延迟。
- 页面不得承诺逐秒同步。

### 12.2 文石 BOOX

当前状态：

- 只有模拟数据。
- 不允许创建正式的文石自动更新订阅。

进入正式范围前必须确认：

- 用户授权方式。
- 书架与阅读记录接口。
- 逐日数据格式。
- 数据更新时间。
- 是否能由设备 APK 本地读取。
- 数据隐私与应用商店政策。

## 13. 接口草案

### 13.1 创建订阅

```http
POST /api/automation/subscriptions
```

请求：

```json
{
  "name": "我的每日月历",
  "dataSource": "weread",
  "scheduleTime": "06:00",
  "timeZone": "Asia/Shanghai",
  "onlyWhenDataChanges": true,
  "templateConfig": {
    "templateKey": "reading_calendar",
    "deviceKey": "leaf5",
    "orientation": "portrait",
    "variant": "doodle",
    "fontKey": "system-hei",
    "selectedMonth": "auto",
    "showCalendarStickers": true,
    "shuffleSeed": 4
  }
}
```

### 13.2 查询订阅

```http
GET /api/automation/subscriptions/{id}
```

### 13.3 修改订阅

```http
PATCH /api/automation/subscriptions/{id}
```

### 13.4 暂停与恢复

```http
POST /api/automation/subscriptions/{id}/pause
POST /api/automation/subscriptions/{id}/resume
```

### 13.5 立即更新

```http
POST /api/automation/subscriptions/{id}/run
```

需要：

- 鉴权。
- 频率限制。
- 幂等保护。
- 返回任务 ID。

### 13.6 查询任务

```http
GET /api/automation/jobs/{jobId}
```

### 13.7 APK 获取 Manifest

```http
GET /api/device/subscriptions/{id}/manifest
Authorization: Bearer <deviceToken>
If-None-Match: "<etag>"
```

返回：

- `200`：存在新版本。
- `304`：没有新版本。
- `401`：设备绑定失效。

### 13.8 设备回执

```http
POST /api/device/subscriptions/{id}/receipts
```

请求：

```json
{
  "version": 28,
  "status": "downloaded",
  "deviceModel": "BOOX Leaf",
  "reportedAt": "2026-07-27T06:10:00+08:00"
}
```

只有设备明确返回 `applied` 时，Web 才能显示“已应用到设备”。

## 16. 安全与隐私

P0 要求：

- Skill Key 只保存在服务端。
- Skill Key 必须使用生产级密钥加密。
- APK 和小程序不得获得 Skill Key 明文。
- 定时接口使用 `CRON_SECRET` 或等效鉴权。
- 每个用户、订阅、图片必须隔离。
- 图片 URL 使用授权接口或有时效的签名 URL。
- 设备 Token 只存哈希。
- 所有任务记录不得打印完整 Skill Key。
- 用户删除连接后，自动任务必须停止。
- 用户删除账号后，清理连接、订阅、设备绑定和图片。

当前公开网页不再使用 `.data/local-connections.json`，服务端不保存 Key。若开发自动任务，必须作为用户主动开启的独立能力，新增账号、数据库、生产级加密与删除机制，不能复用浏览器本地 Key 假定其可在后台运行。

## 17. 非功能要求

### 17.1 性能

- 单张图片生成目标小于 10 秒。
- Manifest 响应目标小于 500 毫秒。
- APK 无新版本检查流量小于 10 KB。
- JPG 建议不超过 3 MB。

### 17.2 可用性

- 定时任务重复触发不得生成重复版本。
- 单个用户失败不得阻塞其他用户。
- 上游接口失败不得清空 Manifest。
- 对象存储发布必须先上传版本文件，再更新 Manifest。

### 17.3 可观测性

日志必须包含：

- `jobId`
- `subscriptionId`
- 数据源
- 配置版本
- 任务阶段
- 耗时
- 重试次数
- 错误码
- 成功版本

不得包含：

- 完整 Skill Key
- 用户完整划线内容
- 图片签名 URL 的长期凭证

## 19. 测试场景

### 19.1 日期与时区

- 北京时间 00:05 的阅读记录显示为当天。
- 时间戳在 UTC 中属于前一天时，仍显示北京时间日期。
- 月末 23:59 和次月 00:01 正确分月。
- 闰年 2 月正确显示。

### 19.2 数据变化

- 新增一天阅读记录。
- 同一天新增第二本书。
- 阅读时长发生变化。
- 划线内容发生变化。
- 没有任何新数据。

### 19.3 模板稳定

- 同一数据连续生成两次，视觉元素位置一致。
- 固定随机种子后贴纸不移动。
- 自定义字体重新生成后不回退系统字体。
- 横竖版和分辨率不变化。

### 19.4 失败

- 微信读书超时。
- Skill Key 失效。
- 字体文件丢失。
- 对象存储上传失败。
- Cron 重复触发。
- APK 下载中断。
- APK 文件校验失败。
- BOOX 存储空间不足。

## 23. 风险与待确认

| 风险 / 问题 | 影响 | 负责人 | 上线前要求 |
| --- | --- | --- | --- |
| 文石真实阅读数据接口未知 | 无法自动更新文石数据 | 产品 / 研发 | 明确 API 或排除首期 |
| BOOX 屏保目录与刷新机制未知 | APK 可能只能下载不能自动应用 | Android 研发 | 真机验证 |
| BOOX 后台省电策略 | 定时任务可能延迟 | Android 研发 | 多设备连续测试 |
| 微信读书 Skill 数据聚合延迟 | 早晨生成可能缺少刚结束的数据 | 后端 | 允许手动更新和重试 |
| 浏览器端 JPG 差异 | 多端图片不一致 | 后端 | 迁移服务端生成 |
| 本地单用户存储 | 无法生产多用户运行 | 后端 | 上数据库 |
| 用户字体授权 | 可能存在版权风险 | 产品 / 法务 | 增加授权确认 |
| Vercel Cron 使用 UTC | 触发时间易配置错误 | 运维 | 明确 UTC 转换 |
| Cron 可能重复触发 | 产生重复图片 | 后端 | 幂等键与锁 |

待产品确认：

1. 默认更新时间是否固定为北京时间 06:00。
2. 首发 APK 只支持 Leaf 系列，还是同时支持 Poke / Note。
3. APK 首期文案承诺“自动下载”还是“自动应用屏保”。
4. 历史屏保保留 7 个版本是否足够。
5. 用户是否可以创建多个每日屏保。
6. Skill Key 失效后是否需要微信服务通知。
7. 小程序是否进入 V1.3，还是只保留 Web + APK。
