# 小文 AI 阅读壁纸生成器｜产品设计文档

> 当前版本：V0.5
> 更新时间：2026-07-17
> 文档用途：统一产品范围、首页布局、数据源、首发模板、生成交互、图片渲染方案和开发顺序。
> 当前阶段：先完成页面、真实数据填充、固定模板渲染和图片下载；文石设备推送作为下一阶段能力。

---

## 1. 产品定位

小文 AI 阅读壁纸生成器是一个面向 BOOX / 墨水屏用户的阅读数据视觉化工具。

用户选择文石阅读或微信读书作为数据源，再选择固定设计模板。系统把真实阅读数据填入预设占位，生成适合目标 BOOX 设备尺寸的黑白 / 灰阶屏保图片。

```text
阅读数据 -> 标准化数据 -> 预设模板 -> 占位填充 -> 生成图片 -> 下载 / 推送设备
```

本产品不以 AI 生图为核心。最终画面由设计师确定，程序负责替换书名、封面、时长、日期、批注等动态内容。

核心价值：

- 把阅读记录变成每天可见、可以持续更新的墨水屏屏保。
- 统一承接文石阅读、微信读书等不同来源的数据。
- 让设计模板与数据逻辑分离，方便后续增加新模板。

## 2. 版本范围

### 2.1 V1.0 首发范围

- 单页首页，无顶部导航。
- 文石阅读、微信读书两个数据源入口。
- 微信读书 Skill Key 激活、验证、删除和数据摘要。
- 4 个首发模板：书柜墙、每周购物小票、本月阅读记录、我的读书卡。
- 点击模板后用弹窗配置和预览，不进入二级页面。
- 支持 BOOX 设备尺寸、横竖屏和自定义尺寸。
- 生成 SVG 预览并下载；设计模板定稿后输出 PNG。

### 2.2 暂不进入 V1.0

- 封面拼贴。
- 阅读本月小票。
- 文案壁纸及用户字体上传。
- 模板市场。
- 自动定时生成。
- 完整的 BOOX 自动推送。

## 3. 首页信息架构

首页按用户提供的布局分成三个全宽区域，不使用顶部导航，也不使用包住整页的大底色卡片。

| 区域 | 内容 | 交互 |
| --- | --- | --- |
| 首屏 | 产品主文案、数据源选择、BOOX 屏保示例 | 点击文石 BOOX / 微信读书切换当前数据源 |
| 微信读书连接区 | Skill Key 输入、激活状态、书架摘要 | 点击微信读书数据源展开 / 收起，支持激活、验证、注销 Skill |
| 屏保类型区 | 字体列表、推送列表、4 个首发模板卡片 | 管理字体、打开 send2boox、点击卡片打开生成弹窗 |

### 3.1 首屏

主文案：

```text
让阅读记录，
变成每天见面的屏保
```

辅助文案：

```text
支持使用文石 BOOX、微信读书的阅读记录
```

右侧展示 BOOX 设备与书柜墙示例，让用户第一眼理解最终产物。

### 3.2 数据源选择

首屏提供两个数据源按钮：

- 文石 BOOX：默认选中；真实接口未接入前使用示例数据。
- 微信读书：显示 Skill 是否已装载；未装载时仍可选择，但生成前需要连接或回退到示例数据。

### 3.3 微信读书连接区

连接区默认收起。用户点击首屏的“微信读书”数据源后展开，再次点击收起；切回“文石 BOOX”时自动收起。展开和收起均在首页完成，不跳转设置页。

未连接状态：

- 输入 Skill Key。
- 点击“激活”。
- 明确 Key 只保存在当前浏览器，并提供获取 Key 的链接。

已连接状态：

- 显示“SKILL 已装载”。
- 只显示脱敏 Key。
- 显示书架条目、电子书和有声书数量。
- 提供“注销技能”。

### 3.4 屏保类型区

桌面端一行展示 4 张卡片，移动端改为单列。卡片由模板预览、名称、短文案组成，不放多余的功能说明。

## 4. 数据源逻辑

### 4.1 数据源总览

| 数据源 | 授权方式 | 当前状态 | 目标用途 |
| --- | --- | --- | --- |
| 文石阅读 | 计划复用文石 Web 端登录态 | 当前使用独立文石模拟数据 | 书架、阅读记录、设备信息与设备推送 |
| 微信读书 | 用户提供 Skill Key | 已接入真实调用链路 | 书架、封面、阅读统计、划线与批注 |

### 4.2 文石阅读

目标方案：产品部署在文石 Web 环境，复用已登录用户身份，读取用户书架和阅读记录。

在正式接口明确前：

- 不伪造“已读取文石真实数据”的状态。
- 使用独立的文石模拟数据验证模板、设备尺寸和图片生成。
- 页面明确显示“文石模拟数据”。
- 模拟数据与微信读书示例数据分开维护，后续接入文石真实接口时只替换数据适配层，不修改模板。

### 4.3 微信读书

调用入口：

```text
POST https://i.weread.qq.com/api/agent/gateway
Authorization: Bearer <用户 Skill Key>
Content-Type: application/json
```

请求示例：

```json
{
  "api_name": "/shelf/sync",
  "skill_version": "1.0.4"
}
```

接口规划：

| 接口 | 用途 | 状态 |
| --- | --- | --- |
| `/shelf/sync` | 获取书架、书名、作者、封面 | 已接入 |
| `/readdata/detail` | 获取阅读天数、时长、阅读书籍 | 已接入 |
| `/book/bookmarklist` | 获取某本书的划线 | 待接入 |
| `/review/list/mine` | 获取个人批注与想法 | 待接入 |

### 4.4 标准化数据结构

所有数据源先转换成统一结构，模板不直接依赖微信读书或文石原始字段。

```ts
type ReadingWallpaperData = {
  source: "boox" | "weread" | "mock";
  books: Array<{
    id?: string;
    title: string;
    author: string;
    coverUrl?: string;
    finished?: boolean;
    lastReadAt?: string;
    progress?: number;
  }>;
  stats: {
    readingDays: number;
    readingMinutes: number;
    bookCount: number;
    noteCount: number;
  };
  calendar: Array<{
    date: string;
    bookId?: string;
    bookTitle?: string;
    readingMinutes: number;
  }>;
  highlights: Array<{
    text: string;
    note?: string;
    bookId?: string;
    createdAt?: string;
  }>;
};
```

## 5. 首发场景模板

| 场景 | 数据来源 | 核心输出 | 主要配置 |
| --- | --- | --- | --- |
| 书柜墙 | 文石阅读 / 微信读书 | 书脊、层板、堆叠和摆件 | 设备、容量、书籍类型、书柜名称、版式、换一批 |
| 每周购物小票 | 文石阅读 / 微信读书 | 周阅读记录、时长、天数、书籍 | 设备、设备编号、订单时间、采购员、条形码、备注、盖章、版式 |
| 本月阅读记录 | 文石阅读 / 微信读书 | 月历、每日阅读、跨日连续阅读 | 设备、月份、月历风格、换一批 |
| 我的读书卡 | 文石阅读 / 微信读书 | 封面、书名作者、进度、心动片段 | 设备、整体评价、版式、换一本 |

右侧预览规则：

- 选择 `BOOX Leaf / Page 系列` 时，生成结果嵌入 Leaf 设备边框的屏幕开口中展示。
- 切换横版时设备边框同步横置，预览图按横屏开口铺满。
- 设备边框仅用于网页预览，下载 JPG 仍为不含外框的纯屏保图片。

### 5.1 书柜墙

文案：在墨水屏感受实体书墙的仪式感。

规则：

- 按最近阅读时间排序。
- 书脊显示书名，过长时自动缩字或截断。
- 支持“全部”“已读完”筛选。
- 当前仅支持 10 本容量模板。
- 真实书少于占位数量时，用不显示书名的装饰书补齐。
- 支持竖向书脊、横向堆叠、植物、地球仪、石膏像等静态摆件。

### 5.2 每周购物小票

文案：本周大脑进货清单，已打印。

采用餐厅“留台单”版式：

- 顶部展示留台单标题、桌号、营业流水、时间、操作人和人数。
- 设备编号映射为桌号，订单时间映射为时间，采购员映射为操作人。
- 阅读书籍映射为品项，作者映射为主厨；书籍产地缺失时显示 `--`。
- 固定展示 5 个书目位置，优先使用本周阅读排行；不足 5 本时按最近阅读时间补齐并去重。
- 每本书优先显示最新划线；没有划线时保留可编辑空白区域。
- 五条书摘编辑区默认折叠，用户手动展开后可逐条修改，再次点击可收起。
- 小票背景使用浅色纸张纤维纹理，纹理随预览和下载文件一起生成。
- 底部展示整单备注、条形码和“阅读天数 + 阅读小时”的账单合计。
- 文石盖章作为可选元素，开启后放在顶部独立空白区。
- 首页场景封面使用 BOOX 设备外框展示同版式留台单缩略图。
- 文石标签下第一版使用模拟周数据：阅读 6 天、485 分钟、5 本书及对应作者、产地和简介。
- 预览底部显示“文石模拟数据”，不与微信读书真实数据状态混用。

### 5.3 本月阅读记录

文案：每天读的书，在日历上都连成线。

规则：

- 只支持本月和上月。
- 日历采用按周分行的阅读条带布局，开始日显示书名、进度或时长。
- 同一本书连续跨日阅读时使用同一种颜色并连接成横向条带；跨周时在下一行延续。
- 同一天阅读多本书时使用最多三条轨道纵向堆叠。
- “可爱”版使用柔和彩色区分书籍，“简约”版使用适合墨水屏的灰阶。
- 展示每日时长、连续阅读天数和月度总时长。

当前微信读书月度接口可提供每日时长，但没有直接返回完整的“日期 -> 书籍”对应关系。因此当前真实数据模式中，日期和时长使用接口数据，跨日书名条带按月度高频书籍稳定排布，并在生成状态中明确说明；后续取得逐书逐日数据后替换映射层。

### 5.4 我的读书卡

文案：一张卡片，记录你进入的世界。

默认选取最近阅读的一本书，展示：

- 顶部“阅读记录卡”标题。
- 左侧书名、作者、类型与用户输入的整体评价，右侧展示书封面。
- 中部内容概要区，底部心动片段与页码区。
- 用户点击“换一本”后依次读取其他书籍。
- 经典版使用蓝色纸张表格视觉，极简版切换为黑白线框。

当前书名、作者、类型和封面可以使用书架真实数据。书籍内容简介、划线内容与页码接口尚未接入：真实数据模式显示待接入状态，示例数据模式填入示例片段，并在生成状态中明确说明。

## 6. 生成弹窗交互

点击场景卡后打开居中弹窗，不跳转二级页面。

| 区域 | 内容 |
| --- | --- |
| 左侧 | 场景名称、数据源、设备、方向、模板专属配置 |
| 右侧 | 根据当前数据和配置自动刷新的预览图 |
| 预览下方 | 手动“刷新预览”，用于重新请求当前参数 |
| 底部 | “推送到设备”占位按钮、下载图片、数据来源与图片尺寸状态 |

交互规则：

1. 打开弹窗后立即请求当前场景需要的数据并生成预览。
2. 修改设备、方向或模板配置后自动刷新预览。
3. 自动刷新使用短暂防抖，连续修改时只采用最后一次请求结果，避免旧预览覆盖新预览。
4. 点击“刷新预览”可用同一组参数重新生成；点击“换一批 / 换一本”改变内容抽取种子。
5. 预览旁明确显示“真实微信读书数据”或“示例数据”，书柜墙额外显示可用封面数量。
6. 点击遮罩或按 `Esc` 关闭弹窗。
7. 下载文件名包含模板 key 和目标分辨率。
8. “推送到设备”在文石接口接入前保持禁用，不伪装成可用功能。

### 6.2 字体列表

场景区右上角左侧按钮为“字体列表”：

- 点击打开字体面板，可搜索系统字体与用户导入字体。
- 内置系统黑体、宋体、楷体、仿宋、等线。
- 支持导入 TTF、OTF、WOFF、WOFF2，单个文件不超过 24 MB。
- 用户可自行导入“仓文”等已获得使用授权的字体。
- 在字体列表中点击字体会设为默认字体；字体选择保存在 `localStorage`，字体文件保存在浏览器 `IndexedDB`。
- 每个场景弹窗提供字体下拉框，可单独切换；切换后右侧预览自动重新生成。
- 自定义字体生成时只提取当前画面出现的字符，转换为 WOFF2 子集后嵌入 SVG，避免把完整中文字体重复写入图片。

公开版不把字体写入服务端。生成时仅将当前选中的字体临时提交进行子集化，请求完成后立即释放。

## 7. 图片渲染方案评估

附件提出“HTML/CSS 模板 + Puppeteer 截图输出 PNG”的方案。结论：**适合本产品，建议作为设计定稿后的正式渲染方案，但不能原样照搬。**

### 7.1 适合的原因

- 设计师可以先在 Figma 中确定版式，开发只负责还原和填充占位。
- HTML/CSS 对中文排版、自动换行、字体加载、图片裁切更友好。
- 同一模板可以填入不同用户的数据。
- 无头浏览器可以直接按 BOOX 目标分辨率输出 PNG。
- 比让 GPT 每次重新生图更稳定、可重复、成本更低。

### 7.2 原方案需要修正

| 原方案 | 问题 | 调整决定 |
| --- | --- | --- |
| 所有模板只维护一份，所有设备只按宽度缩放 | BOOX 设备宽高比差异较大，可能裁切或留空 | 按比例分为窄长屏、标准竖屏、横屏三类基础画布 |
| CSS 禁止使用 px | 固定输出画布本身就需要精确像素 | 画布和关键位置允许 px，弹性区域使用 `%`、`rem`、Grid |
| 先设置内容，再设置 viewport | 页面可能按错误尺寸排版后再截图 | 先设置 viewport，再加载模板和字体 |
| 逐字宽度截断 | 中文、英文和混排测量容易出错 | 优先用 CSS 行数限制，再用 Canvas/TextMetrics 兜底 |
| 每次生成都启动浏览器 | 冷启动慢、内存高 | 复用 Chromium 实例或浏览器池 |
| 依赖 CDN 资源 | 网络波动会导致封面或字体缺失 | 生成前把封面、字体、静态素材缓存为本地或 Data URI |
| `fullPage: true` 截图 | 页面内容超高时会输出错误尺寸 | 截取固定画布元素，严格输出目标宽高 |

### 7.3 推荐技术选型

当前 Demo 继续使用 SVG 模板，便于快速验证产品逻辑。设计稿和占位规范稳定后迁移为：

```text
Figma 设计稿
  -> HTML/CSS 模板 + 静态素材
  -> 标准化阅读数据
  -> 模板占位填充
  -> Playwright / Puppeteer + Chromium 截图
  -> Sharp 灰阶、压缩和尺寸校验
  -> PNG 下载 / 推送
```

Puppeteer 和 Playwright 都可实现。当前项目是 Next.js，推荐优先使用 Playwright 或 Puppeteer Core，并在独立 Node 服务或支持 Chromium 的容器中运行。若部署到 Vercel，需要额外配置轻量 Chromium，部署复杂度高于普通 Next.js API。

## 8. 设计师交付与占位规范

具体图片数量、母版尺寸、切图格式和验收清单见 [`design-asset-checklist.md`](design-asset-checklist.md)。

只提供一张合并后的 PNG 不够，因为程序无法单独替换文字和书封。设计交付应为“可替换占位版设计稿”。

推荐交付内容：

- Figma 源文件。
- 每个模板的基准画布和比例类型。
- 静态背景、纹理、装饰分别导出为 SVG / PNG。
- 所有动态文字保持为独立文字层。
- 所有封面保持为独立图片框。
- 字体名称、授权文件、字号、颜色、行高、最大行数。
- 空数据、短数据、长数据三种示例。

动态层命名示例：

```text
{{shelf_title}}
{{book_title_01}}
{{book_cover_01}}
{{reading_minutes}}
{{reading_days}}
{{month}}
{{highlight_01}}
{{note_01}}
```

开发侧为每个动态层维护占位表：

| 字段 | 类型 | 位置 | 约束 | 降级方案 |
| --- | --- | --- | --- | --- |
| `book_title_01` | 文本 | x/y/w/h | 最多 8 字，竖排 | 缩字后截断 |
| `book_cover_01` | 图片 | x/y/w/h | `cover` 裁切 | 灰色占位封面 |
| `reading_minutes` | 数字 | x/y/w/h | 最大 6 位 | 显示 0 |
| `highlight_01` | 文本 | x/y/w/h | 最多 4 行 | 显示空状态 |

首轮只让设计师完成 2 个模板：书柜墙和每周购物小票。数据填充和输出稳定后，再继续本月阅读记录和我的读书卡。

## 9. 图片生成接口

当前接口：

```text
POST /api/wallpapers/generate
```

请求字段：

| 字段 | 说明 |
| --- | --- |
| `templateKey` | 模板 key |
| `deviceKey` | BOOX 设备 key |
| `orientation` | 竖屏 / 横屏 |
| `variant` | 模板风格 |
| `customTitle` | 自定义标题或文案 |
| `shuffleSeed` | 换一批种子 |
| `dataMode` | `mock` 或 `weread` |
| `customWidth` | 自定义宽度 |
| `customHeight` | 自定义高度 |
| `shelfCapacity` | 书柜容量：当前固定为 10 本 |
| `bookFilter` | 书本类型：全部 / 已读完 |
| `receiptDeviceNumber` | 小票设备编号 |
| `receiptOrderTime` | 小票订单时间 |
| `receiptBuyer` | 小票采购员 |
| `showBarcode` | 是否显示条形码 |
| `showReceiptNote` | 是否显示小票备注 |
| `receiptNote` | 小票备注内容 |
| `showBooxStamp` | 是否显示文石盖章 |
| `selectedMonth` | 月历月份，格式 `YYYY-MM` |
| `overallRating` | 读书卡整体评价 |
| `fontKey` | 系统字体或用户导入字体 key |

当前输出为 SVG Data URL。正式渲染服务接入后，接口改为返回 PNG 文件地址或二进制流，并增加：

- 输出文件过期时间。
- 模板版本。
- 数据来源和生成时间。
- 图片尺寸与校验结果。

## 11. 隐私与安全

- Skill Key 属于敏感信息，不在页面完整显示。
- Skill Key 不写死在代码、不提交 GitHub。
- Skill Key 只保存在用户当前浏览器的 `localStorage`，服务端不落盘。
- 用户可以注销 Skill，并从当前浏览器删除 Key。
- 服务端日志不得记录 Authorization 请求头。
- API 响应使用 `Cache-Control: no-store`，不持久化书封、划线、批注和生成图片。
- 所有真实数据请求显式携带本次浏览器中的 Key，不使用全局连接状态。

## 12. 状态与异常

| 状态 | 页面反馈 | 生成策略 |
| --- | --- | --- |
| 微信读书未连接 | 显示“未连接”与 Key 输入 | 提示连接或使用示例数据 |
| Skill 验证中 | 按钮显示“验证中” | 禁止重复提交 |
| Skill 已装载 | 显示脱敏 Key 与书架摘要 | 使用真实数据 |
| 数据为空 | 显示空数据说明 | 使用空状态模板，不伪造真实记录 |
| 封面缺失 | 单本书显示默认封面 | 其他数据继续生成 |
| 图片生成失败 | 显示可理解的错误和重试按钮 | 不覆盖上一次成功结果 |
| 设备推送失败 | 显示失败原因和重试 | 保留已生成图片供下载 |
