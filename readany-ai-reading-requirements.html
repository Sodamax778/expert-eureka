1. 背景与目标

传统阅读器以「关键词搜索 + 本地批注」为主，难以回答「按意思找段落」「跨章节归纳」「针对划线追问」等需求。 AI 阅读在用户自带书库与阅读位置上下文的前提下，提供可溯源的对话、语义检索与结构化阅读辅助，并尽量保护隐私与阅读节奏（可选防剧透）。

产品目标（可衡量方向）

  • 理解：用户能用自然语言提问，答案应优先基于当前书/当前上下文，而非泛泛闲聊。
  • 可信：涉及书内事实时，应能关联到可点击跳转的书内位置（引用 / 定位）。
  • 可控：用户可选择模型与密钥、是否向量化建库、是否开启防剧透；敏感内容尽量本地化处理。
  • 效率：划词、附文提问、多轮对话成本低；长书检索有合理耗时与结果条数上限。

2. 用户与核心场景

角色典型场景期望结果
深度读者 读到某段不理解，划词后问「这段话在全书里和什么观点呼应？」 结合选文 + RAG/工具取书内材料，回答并给可跳转引用
研究者 需要按主题在全书找论述，并对比两章论点 语义/混合检索 + 章节级分析工具 + 引用注册
休闲读者 不想被剧透结局，但想讨论已读部分 防剧透模式下限制对「未读之后」内容的检索与回答
技能型用户 一键做摘要、概念卡、论证拆解、阅读导引 内置或可配置「技能」提示词 + 参数，输出格式稳定

3. 功能需求

3.1 阅读上下文（Reading Context）

  • FR-RC-01：系统应维护当前打开书籍标识、书名、当前章节标题与索引、阅读进度（百分比/位置）、当前页可见正文摘要（周围文本）。
  • FR-RC-02：用户划选文本时，应记录选中文本、书内定位（如 CFI）、章节索引；用于气泡操作与后续 AI 工具 getSelection 拉取。
  • FR-RC-03（可选增强）：将「语义阅读上下文（章、活动类型、周围文本、最近高亮）」注入系统提示，便于模型在不增加工具往返时理解场景。
  • FR-RC-04：选区取消或离开阅读器时的行为需明确（清空服务层选区或保留至下次覆盖），避免工具读到陈旧选区。

3.2 对话与多轮（Chat）

  • FR-CH-01：支持在当前书范围内建立会话线程；历史消息需做窗口截断（滑窗大小可配置）以控制成本与上下文长度。
  • FR-CH-02：支持用户消息中附带引用块（划词「问 AI」进入输入框）：将摘录以引用形式与用户问题拼接，模型优先围绕摘录作答。
  • FR-CH-03：支持流式输出 token、可选「推理/思考」内容单独展示（依赖具体模型能力）。
  • FR-CH-04：支持中止生成。
  • FR-CH-05：助手消息应能保存工具调用轨迹、引用列表，便于导出或二次展示。

3.3 系统提示与行为规范

  • FR-SP-01：系统提示应明确角色：不得用训练数据冒充本书内容；书内相关问题须先通过工具/RAG 获取材料再作答。
  • FR-SP-02：系统提示应列出可用工具类别（书库、阅读上下文、RAG、分析、批注、引用注册、技能查询等），并规定工具调用纪律（避免同义重复检索、结果足够即停等）。
  • FR-SP-03：响应语言策略需统一（例如与用户一致或固定中文/英文），并与 UI 多语言策略一致。
  • FR-SP-04：允许在Markdown 中嵌入 Mermaid 图表；思维导图类需求可走专用工具而非 Mermaid。

3.4 RAG 与全书检索

  • FR-RG-01：对已完成向量化/分块的书籍，提供混合检索（语义 + 关键词/BM25），返回结果须含可定位字段（如 CFI）与片段正文。
  • FR-RG-02：提供目录/章节结构查询能力，便于模型先做结构规划再做分章检索或摘要。
  • FR-RG-03：支持按章节范围拉取邻近正文，用于精读某一位置。
  • FR-RG-04：对检索结果总长度设 token/字符上限，避免单次工具返回撑爆上下文。
  • FR-RG-05：未向量化的书：应明确降级策略——仅依赖当前页/选区/用户粘贴，或提示用户先建索引。

3.5 工具化能力（Agent）

模型以 ReAct 风格多轮调用工具。需求上按域拆分（与实现命名可不同）：

域能力说明
书库与笔记列出书籍、跨书搜索高亮/笔记、阅读统计等
阅读上下文当前章、进度、选区、最近高亮、当前页可见文本
RAG全书检索、目录、按章上下文
内容分析摘要、实体抽取、论证分析、金句、章节对比等（通常依赖已切块数据）
批注读取用户高亮/笔记类型数据
可视化思维导图等结构化输出
技能查询可用技能列表；按技能 ID 执行时返回技能长提示 + 参数供模型遵循

3.6 引用与书内溯源（Citation）

  • FR-CT-01：模型在陈述书内事实、引用、情节、数据时，应通过注册引用与正文中的 [1]、[2] 等形式对应。
  • FR-CT-02：每条引用须绑定可跳转定位（CFI 等）与简短摘录（长度上限如 200 字以内，可配置）。
  • FR-CT-03：UI 须支持用户点击引用标记跳转阅读位置。
  • FR-CT-04：在历史消息回放时，引用信息可注入到消息文本末尾（便于多轮连贯），具体格式需与导出一致。

3.7 技能（Skills）

  • FR-SK-01：内置多类技能（如摘要、概念解释、论证分析、人物、金句、阅读向导、翻译、词汇等），每类含结构化提示词（步骤、版式、约束、示例）。
  • FR-SK-02：用户可开关内置技能；可新增自定义技能（名称、描述、参数模式、提示词）。
  • FR-SK-03：主对话路径中，技能可作为工具暴露；亦可提供直达执行路径（仅系统提示 + 技能提示 + 参数起一次模型调用）。

3.8 防剧透模式

  • FR-SF-01：用户可开启「防剧透」：系统提示约束模型不得透露当前阅读位置之后的叙事信息。
  • FR-SF-02：应禁止或限制会拉取「未读章节」内容的工具调用；用户坚持追问时应礼貌拒绝并引导继续阅读。
  • FR-SF-03：防剧透判定依赖可靠的「当前章/进度」信息；若该信息缺失，应降级提示或保守处理。

3.9 模型与连接

  • FR-MD-01：支持多供应商、多 Endpoint、可配置 API Key、Base URL、模型列表。
  • FR-MD-02：支持本地推理（如 Ollama）与云端 API；流式与非流式兼容策略明确。
  • FR-MD-03：对需多轮工具调用的「推理模型」保留历史中的推理字段，避免会话报错。
  • FR-MD-04：嵌入/向量化模型可与聊天模型分离配置（本地 HF 管线等）。

4. 关键用户流程

4.1 划词问 AI

  1. 用户在阅读器划选文本 → 系统记录选区与定位。
  2. 用户点击「问 AI」→ 打开侧边对话（或唤起输入）并附带摘录 Chip。
  3. 用户输入问题（可仅发送摘录）→ 将「关于以下文本… + 引用块 + 问题」送入对话。
  4. 模型按需调用工具（如 getSelection、ragSearch）并流式输出。
  5. 涉及书内事实时注册引用，用户点击 [n] 跳转。

4.2 全书主题检索问答

  1. 书籍已完成向量化。
  2. 用户在对话中提出主题问题 → 模型调用 RAG 检索 → 必要时多工具组合（目录 / 分章摘要）。
  3. 回答中注册引用，避免重复无效检索。

4.3 使用技能

  1. 用户在设置中启用技能（内置/自定义）。
  2. 对话中模型通过「查询技能」工具匹配任务 → 调用对应技能工具获取长提示 → 按提示生成。
  3. 或使用直达执行：选择技能 → 填参 → 单次模型调用产出结构化结果。

5. 非功能需求

  • NFR-01 隐私：书稿与向量索引默认落在用户设备或可信任存储；密钥不落日志明文。
  • NFR-02 性能：流式首字时间、单次 RAG 延迟、工具链路过长时的超时与取消。
  • NFR-03 可访问：聊天与阅读器联动时焦点管理、键盘操作。
  • NFR-04 合规：爬虫/版权内容提示由产品声明；AI 输出免责声明可按需要展示。
  • NFR-05 离线：本地模型与本地向量库场景下核心阅读 + 本地 RAG 可用性定义。

6. 边界、风险与验收要点

幻觉与漏检：RAG 分块与检索 Top-K 会导致漏答或断章取义；需在文案与设置中管理预期，并提供「再次检索不同关键词」等引导而非静默重试滥用。
验收抽查建议
  • 无索引书：仅附文提问仍能回答摘录相关；不出现伪造章节名。
  • 有索引书：事实句带可跳转引用；引用 CFI 有效。
  • 防剧透开：追问结局应拒绝且不调用后续章节工具。
  • 划词清除后：「问 AI」未附文时，getSelection 行为符合定义（空/错误提示）。
  • 长会话：滑窗后仍能完成简单跟进问题（或明确遗忘边界）。
